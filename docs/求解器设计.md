# 求解器设计

> 当前方案 · DFS 打到结束 + 层 2 记忆化出牌 + 加权统计

---

## 1. 要算什么

对每条**完整抽牌路线** ω（从战斗开始到击杀为止的各回合上手组合）：

1. 假设玩家知晓当前及未来上手（SL 完美信息），采用**最小化整场总战损**的出牌；
2. 得到该路线的 **D(ω)** = 最优总战损；
3. 得到该路线的 **w(ω)** = 在真实洗牌规则下该路线出现的（条件）概率权重。

汇总时**不等权**：

| 指标 | 公式 |
|------|------|
| 加权必伤概率 | \( P(D>0) = \sum_{ω: D(ω)>0} w(ω) \big/ \sum_ω w(ω) \) |
| 加权期望战损 | \( \mathbb{E}[D] = \sum_ω w(ω)\, D(ω) \big/ \sum_ω w(ω) \) |
| 战损分布 | 按 \(w(ω)\) 加权直方图 / 分位数 |

怪物 HP 为区间时（如海洋混混 47–49），**每个 HP 各算一遍**。

## 2. 总体架构

```
DFS 展开抽牌树（直到击杀）
  每步：从 draw/discard 枚举上手组合 + 累乘 step 权重
  节点：层 2 最优出牌（记忆化 DP + 剪枝）
  叶：enemy_hp <= 0 → 记录 (ω, w(ω), D(ω), trace)
```

**不推荐 BFS**：需同时持有「第 k 回合仍存活」的全部前缀，前沿随回合指数膨胀，且无法自然利用早杀剪枝。

**动态规划用在两处**：

| 位置 | 作用 |
|------|------|
| **层 2 出牌** | 自顶向下记忆化：最小总战损，可回溯一条最优出牌序列 |
| **（可选，后续）** | 同一「回合初局面」汇合时，缓存子树战损直方图，避免重复后缀枚举 |

**不用**「定长 N 回合预枚举全部路径再逐条求解」：会（1）对已击杀路线继续枚举无意义抽牌；（2）N 回合截断会**低估**长局鬼抽的真实战损。

---

## 3. 两层职责

### 层 1：抽牌（DFS 驱动）

- 按《抽牌枚举协议》在每一步从牌堆/弃牌堆做**多重集组合**分支（不枚举牌序）。
- **击杀后不再抽牌**——该路线在叶节点结束。
- 每分支携带 **step_weight**；叶节点 **w(ω)** = 沿途 step_weight 之积。
- 弃牌堆组成仅由抽牌路径决定，与出牌无关（见协议 §7）。

单步权重（组合多重数）：

```text
ways(pool, drawn) = ∏ᵢ C(pool[i], drawn[i])     （drawn[i] ≤ pool[i]，∑drawn = k）
P(step) = ways / C(∑pool, k)
```

枚举的是**不同组合**；权重补上被合并的物理条数，使期望与分布正确。

### 层 2：出牌（固定当前与未来上手下的最优决策）

- **输入**：玩家回合初完整局面（已抽满 5 张或不足但抽牌阶段结束）。
- **输出**：`min_damage`；后续版本另输出分回合 `trace`（见 §8）。
- **目标**：从该局面到战斗结束的**最小总战损**（非单回合贪心）。
- **记忆化**：每条 DFS 路线使用**路径内 memo**（`_PathSolver`），路线结束即释放；**禁止**跨路径无限增长的全局 `lru_cache`（曾导致 OOM）。

## 4. 终止条件（层 1 何时停止延长抽牌前缀）

对每条抽牌前缀（长度 t），求两个量：

对每条抽牌前缀（长度 t），需两个量：

| 量 | 含义 |
|----|------|
| `surv` | 仅生存 t 回合（不要求击杀）的最小累计战损 |
| `best_kill` | 在 ≤t 回合内**击杀**的最小累计战损 |

`surv` 是**任意更长 ω 的战损下界**（未来击杀只能从某个存活线分叉，故代价 ≥ 当前最小存活战损）；`best_kill` 非增、`surv` 非减。

| 条件 | 行为 |
|------|------|
| **`best_kill ≤ surv`** | 再延长不可能出现更便宜的击杀 → 叶节点，记录 `(w, best_kill)` |
| 否则 | 延长：回合末更新牌堆，枚举下一回合抽牌组合继续 DFS |
| （保险丝）`turn > hard_turn_cap` | 仅防实现 bug，**不参与**统计口径 |

**实现（增量前沿 DP）**：`solve_encounter` 沿抽牌 DFS 维护「战斗状态前沿」`{回合初战斗状态 → 最小累计战损}`；每回合用 `within_turn(cs, hand)` 枚举本回合所有合法出牌，得到 (是否可击杀, {下一回合初状态 → 本回合额外战损})，O(1 回合) 把前沿推进一步并更新 `best_kill` / `surv`。因牌堆演化与出牌无关，前沿可在 DFS 间**增量复用**，无需每前缀从头重解。

> ⚠️ **不能一见「本回合可击杀」就停**。为在更早回合凑出致死伤害，往往要牺牲格挡、全力进攻，反而多吃敌人攻击；先垫防御、拖到更晚回合击杀可能总战损更低。必须等到 `best_kill ≤ surv` 才确定 `D(ω)`。
>
> 历史教训：早期实现用「回合初满手牌 + 当前敌血」近似判断可击杀（高估击杀力）来算 `killd`，产生 **phantom（假击杀）**，把「龟缩生存战损」误记为「击杀战损」，HP47 下 99.99% 权重被低估（E 从真实 ~7.58 误算成 ~5.37）。前沿 DP 用 `within_turn` 精确枚举本回合，杜绝该误差。

**不采用**「固定 N 回合后取当前战损」作为统计结果——会低估极限长局下的战损。

铁甲战士 vs 海洋混混：敌人 HP 有限、伤害有限，最优出牌下**总会击杀**；试点实测最深停止回合 = 8。

## 5. 层 2 单回合剪枝规则

以下在**最小化整场总战损**目标下对本试点成立：

### 5.1 可击杀 → 必须击杀（仅限本回合初的**给定局面**内）

若**在当前回合初局面下**本回合存在出牌序列使 `enemy_hp <= 0`，则该局面的最优策略必在其中（击杀即终止后续敌人攻击）。剪枝：

- 不扩展「未击杀就结束回合」；
- 已击杀后不再继续出牌。

> ⚠️ 此规则是**局部**的：它基于「已经到达」的回合初局面。它**不**意味着「应尽早在抽牌树里凑出可击杀」——是否提前击杀属于跨回合的格挡/进攻权衡，由层 2 DP 对全前缀取最优、并由 §4 停止条件（`best_kill ≤ surv`）共同决定。

### 5.2 格挡已够 → 剩余费用打攻击

若当前格挡已完全吸收本回合意图伤害（`incoming_damage == 0`），则：

- 不再打防御；
- 若有可出的攻击且仍有能量，**不可空过结束回合**。

### 5.3 无防御可打 → 剩余费用全力攻击

当手牌中**已无可出的防御牌**，且仍有能量时：

- 只扩展攻击分支；
- 不可空过。

**示例**：第一回合意图 13 伤，上手 **1 防 3 打 1 诅咒**（诅咒不可打出）。只有 1 张防，故只有：

- 0 防：3 打；
- 1 防 + 2 打。

「1 防 1 打」被同格挡下少打攻击支配；不存在「打 2 防 / 3 防」分支。

### 5.4 未剪枝部分

- 痛击与打击的**顺序**（易伤）仍须在层 2 内取最优；
- **打几张防**（在尚不够格挡时）属于全局权衡，不能只靠单回合局部规则删到一条。

## 6. 局面（State）

类型见 `engine/types.py`。手牌与牌堆均为 `(打击, 防御, 痛击, 诅咒)` 张数。

| 字段 | 含义 |
|------|------|
| `hand` / `draw` / `discard` / `exhaust` | 四堆多重集 |
| `hand_at_turn_start` | 本回合初上手牌（回合末弃牌入堆用，与出牌无关） |
| `enemy_*` / `intent_index` | 敌人状态 |
| `player_*` | 玩家格挡与 buff |
| `damage_taken` / `turn_count` | 累计战损与回合 |

---

## 7. 内存策略

1. **路径内 memo**：单条 ω 的层 2 缓存随 `_PathSolver` 实例销毁而释放。
2. **流式聚合**：`solve_encounter` 不保存全部 `D(ω)` 列表（除非导出）；只累计加权直方图与 min/max。
3. **定期 `gc.collect()`**：长跑时可配置间隔（`--gc-interval`）。

## 8. 输出路线图

### 8.1 第一版（尽量简单）

- [x] DFS / 定长路径原型与层 2 剪枝（当前 `engine/` 部分实现）
- [x] **改为 DFS 打到击杀**（增量前沿 DP，停止条件 `best_kill ≤ surv`，见 §4）
- [x] 叶节点 **加权** 汇总：`P(必伤)`、`E[D]`、min/max、加权分布（`Fraction` 精确权重）
- [x] 命令行进度反馈（`--progress`，支持未知总数）
- [x] 类型 `PathResult`、`TurnTrace`（`engine/types.py`）

### 8.2 第二版（可信度与溯源）— ✅ 已实现

`run_pilot.py --export DIR` 对每个 HP 写 `route_hp{HP}.jsonl`，每行一条 ω（含 `weight` / `weight_frac` 精确分数、`min_damage`、`opening_hand`、逐回合 `plays` 与 `enemy_hp`）。导出叶子的出牌迹由精确 `_PathSolver`（`accurate_lethal`）重建。

每条路线 ω 持久化，例如 JSONL：

```json
{
  "weight": 0.000131,
  "min_damage": 8,
  "opening_hand": [2, 2, 1, 0],
  "turns": [
    {
      "turn": 1,
      "hand": [2, 2, 1, 0],
      "plays": ["B", "S", "S"],
      "damage_after": 8,
      "enemy_hp": 39
    }
  ]
}
```

用途：

- 加权期望 / 分布与明细一致，可复核；
- 按上手、战损筛选代表路线；
- 可选只导出子集（高战损、高权重）以控制体积。

### 8.3 第三版（可选优化）

- 汇合 memo：`(战斗, 牌堆, 手牌) → Counter(min_damage → weight)`，合并重复后缀。

## 9. 实现状态（`engine/`）

| 模块 | 状态 |
|------|------|
| `load_data.py` | 从 `data/sts2/*.json` 构建牌组/卡牌数值/敌人意图；`deck.py`、`combat.py` 的数值常量由此加载（去硬编码） |
| `combat.py` | 战斗转移、意图伤害、剪枝辅助（`can_kill_this_turn` 等）；数值常量 ← `load_data` |
| `deck.py` | 多重集牌堆、组合抽牌、`combination_weight`（组合多重数）；`IRONCLAD_A10_DECK` ← `load_data` |
| `draw_scheduler.py` | 组合抽牌；带权单步枚举 `weighted_opening` / `weighted_draw_at_turn_start`；定长枚举保留供测试 |
| `solver.py` | **增量前沿 DP `solve_encounter`（打到击杀 + 加权 + 可选导出）** + `within_turn`；`_PathSolver`（`truncate`/`accurate_lethal` 双语义）、`solve_prefix_killable` 供导出与逐叶复核 |
| `progress.py` | 终端进度条（支持未知总数 indeterminate） |

**以本文档为准**；与定长 8 回合、等权 `P(必伤)`、全局 `lru_cache` 相关的旧描述作废。

> ✅ 正确性验证：
> - **逐叶复核**：前沿 DP 记录的每个叶子的 `best_kill`，与对该前缀用精确 `_PathSolver`（`accurate_lethal`）独立求得的击杀最小战损**完全一致**（HP47 抽样 1200 叶 0 不符）。
> - **导出回放**：HP47 全部 3318 条 JSONL 出牌迹回放后均击杀且累计战损 = `min_damage`；权重和精确 = 1；JSONL 分布与求解器分布逐项一致。
> - **结果**：HP 47/48/49 → P(必伤)=1.0，E[D] ≈ 7.58 / 7.74 / 8.91，区间 3–31，最深停止回合 = 8，无截断。
>
> ⚠️ 早期「定长足够深 + 带权」与旧 DFS 曾「逐项一致」于 E≈5.37，但二者**共享同一缺陷**（生存截断语义 + 近似击杀判定），并非真正打到击杀，已作废。
