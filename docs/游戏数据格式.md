# 游戏数据格式

> 静态 JSON + Markdown，不与游戏本体联动。  
> 求解器从 `engine/load_data.py` 加载试点数值；角色/遭遇数据见 `data/{sts1,sts2}/`。

---

## 1. 目录约定

```text
data/
├── sts1/                    # 塔1（characters 已建；encounters 待录，结构同 sts2）
└── sts2/
    ├── cards/               # 单卡定义，一卡一文件
    │   └── {card_id}.json
    ├── characters/          # 角色初始牌组与遗物说明
    │   └── {character_id}.json
    ├── encounters/          # 遭遇战（含怪物意图、血量）
    │   └── {encounter_id}.json
    └── pilot_*.md           # 某场试点的设定摘要（人类可读，非机器加载）
```

- **`id`**：英文 snake_case，文件名与 JSON 内 `id` 一致。
- **塔1 / 塔2** 分目录；同一张通用卡（如打击）在两作中可各有一份 JSON（数值不同时）或共用（未强制，按录入方便为准）。
- **进阶**：怪物与部分数值用 `low` / `high` 两档；塔2 高进阶对标 **A10**，塔1 对标 **A20**（见 `docs/项目计划书.md`）。

## 2. 卡牌 `cards/*.json`

### 2.1 通用字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✓ | 与文件名相同 |
| `name` | string | | 中文名（展示用） |
| `cost` | int | 攻击/技能通常必填 | 能量费用；诅咒等不可打出可无 |
| `type` | string | | `attack` \| `skill` \| `power` 等 |
| `target` | string | | `enemy` \| `self` 等 |
| `unplayable` | bool | | `true` 表示不能被打出 |
| `keywords` | string[] | | 见 §2.3 |
| `damage` | int | | 攻击单次基础伤害（多段另字段） |
| `block` | int | | 技能获得的基础格挡 |
| `effects` | object[] | | 附加效果，见 §2.4 |

### 2.2 示例

**打击** `strike.json`：

```json
{
  "id": "strike",
  "name": "打击",
  "cost": 1,
  "type": "attack",
  "damage": 6,
  "target": "enemy"
}
```

**痛击** `bash.json`（先伤害后易伤）：

```json
{
  "id": "bash",
  "name": "痛击",
  "cost": 2,
  "type": "attack",
  "damage": 8,
  "target": "enemy",
  "effects": [
    {
      "type": "apply_vulnerable",
      "amount": 2,
      "order": "after_damage"
    }
  ]
}
```

**进阶之灾** `ascenders_bane.json`：

```json
{
  "id": "ascenders_bane",
  "name": "进阶之灾",
  "unplayable": true,
  "keywords": ["eternal", "ethereal"]
}
```

### 2.3 词条 `keywords`

| 值 | 含义 |
|----|------|
| `eternal` | 永恒（局外；不影响局内消耗/变牌） |
| `ethereal` | 虚无（回合末仍在手则消耗） |
| `exhaust` | 消耗（打出后进消耗堆） |
| `retain` | 保留（回合末保留在手） |
| `summon` | 召唤（亡灵契约师：召唤奥斯提） |
| `sly` | 奇巧（静默猎手；首场初始牌不涉及） |

完整战斗语义见 `docs/游戏机制.md` §9。

### 2.4 效果 `effects[]`

| `type` | 字段 | 说明 |
|--------|------|------|
| `apply_vulnerable` | `amount`, `order` | 给予易伤；`order`: `after_damage` \| `before_damage` |
| `apply_weak` | `amount`, `order` | 给予虚弱 |
| `gain_block` | `amount` | 获得格挡（技能主效果已用 `block` 时不必重复） |
| `discard` | `count` | 弃手牌张数（玩家选择） |
| `channel` | `orb`, `amount` | 生成充能球（故障机器人；`orb`: `lightning` 等） |
| `evoke` | `orb`, `times` | 激发充能球；`orb`: `rightmost` 等 |
| `gain_stars` | `amount` | 获得辉星（储君；可跨回合保存） |
| `summon` | `amount` | 召唤奥斯提（见 `docs/角色战斗机制.md` 召唤词条） |
| `enter_stance` | `stance`, `stance_name` | 进入姿态：`wrath`愤怒 / `calm`平静 / `divine`神格 |
| `gain_energy` | `amount` | 获得能量 |
| （待扩展） | | 多段 `hits`、奥斯提攻击等按需追加 |

卡牌可同时有 `cost`（能量）与 `star_cost`（辉星，储君专用）。

多段伤害在**怪物意图**里用 `hits`；卡牌多段若录入，建议 `damage` + `hits`。

## 3. 角色 `characters/*.json`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 角色 id |
| `name` | string | 中文名 |
| `starting_deck` | object[] | `{ "card": "<card_id>", "count": n }` |
| `relic` | object | 遗物说明（可选） |
| `relic.id` | string | 遗物 id |
| `relic.in_combat` | bool | 是否参与**战斗内**模拟 |
| `relic.in_combat` | bool | 是否参与**战斗内**模拟 |
| `relic.note` | string | 备注（如燃烧之血仅战后回血） |
| `first_fight_model` | object | **首场弱怪战斗**的抽牌/机制范围（见 §3.1） |

示例见 `data/sts2/characters/ironclad.json`。机制人类可读详述见 `docs/角色战斗机制.md`。

**牌组引用**：`starting_deck[].card` 必须对应 `cards/` 下已有 `id`。

### 3.1 首场模型 `first_fight_model`

| 字段 | 类型 | 说明 |
|------|------|------|
| `solver_status` | string | `supported` \| `data_only` \| `blocked` |
| `draw.regular_hand_size` | int | 第 2 回合起每回合摸牌数（通常 5） |
| `draw.opening_hand_size` | int | 第 1 回合上手张数 |
| `draw.opening_hand_source` | string | `default` \| `relic` |
| `draw.deck_includes_ascenders_bane` | bool | 牌组是否含进阶之灾 |
| `draw.discard_pile_coupled_to_plays` | bool \| `"bane_only"` | 可选；猎手为 `"bane_only"`：仅生存者弃诅咒改变牌池 |
| `first_fight_scope.in_scope` | string[] | 首场模拟要实现的机制 |
| `first_fight_scope.out_of_scope` | string[] | 先录数据、求解器暂不实现 |
| `first_fight_scope.relic_combat` | object[] | 战斗内遗物（结构化，见 `docs/角色战斗机制.md`） |
| `first_fight_scope.path_flags` | object | 可选；导出用路径标记，如 `active_curse_discard`（主动弃诅咒） |
| `mechanics_doc` | string | 指向机制文档锚点 |

## 4. 遭遇战 `encounters/*.json`

一场遭遇可含多只怪；首场弱怪多为单怪。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 遭遇 id |
| `name` | string | 显示名 |
| `act` | int | 层数 |
| `pool` | string | 如 `weak`（弱怪池） |
| `biome` | string | 区域（可选） |
| `monsters` | object[] | 怪物列表 |
| `notes` | string[] | 自由备注 |

### 4.1 怪物 `monsters[]`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 怪物 id |
| `name` | string | 中文名 |
| `max_hp` | object | 见下 |
| `moves` | object[] | 意图列表 |
| `pattern` | object | 意图循环 |

**`max_hp`**：

```json
{
  "low": { "min": 44, "max": 46 },
  "high": { "min": 47, "max": 49 },
  "solve": "enumerate_each"
}
```

| `solve` | 含义 |
|---------|------|
| `enumerate_each` | 对 `[min, max]` 内**每个整数 HP 分别求解**，不合并 |

### 4.2 意图 `moves[]`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 如 `A`, `B`, `C` |
| `intent` | string | `attack` \| `defend_buff` \| … |
| `damage` | int 或 `{low, high}` | 单段攻击基础伤害 |
| `hits` | int | 段数；总伤 = 单段（含力量等）× 段数规则见机制文档 |
| `block` | int 或 `{low, high}` | `defend_buff` 获得格挡 |
| `strength` | int 或 `{low, high}` | `defend_buff` 获得力量 |

**`pattern`**：

```json
{
  "opening": "A",
  "cycle": ["A", "B", "C"]
}
```

- 开战第一轮固定 `opening`；之后按 `cycle` 循环。
- **随机意图**（如污泥旋转者）：`"type": "random_no_repeat"`，首回合仍用 `opening`，之后从 `cycle` 随机且不可连选同一招。

**`powers[]`**（怪物被动，可选）：

| 字段 | 说明 |
|------|------|
| `id` | 如 `thorns`, `ravenous` |
| `type` | `intensity` 等 |
| `amount` | 层数/强度（可 `{low, high}`） |

**多怪遭遇**：`monsters[]` 可加 `count`；各只起手意图错开时用 `pattern_offset`（整数，表示 cycle 中的起始下标）或写在 `notes`。

### 4.3 数值档位

- 标量（如 `damage: 2`）：两进阶相同。
- `{ "low": n, "high": m }`：低进阶 / 高进阶（A10 或 A20）采用值。
- 括号约定与 `docs/游戏机制.md` §6 一致。

## 5. 试点说明 `pilot_*.md`

人类可读的单场设定摘要（角色、怪物、进阶、求解约定），**不是**机器加载的 schema。  
例：`data/sts2/pilot_ironclad_vs_seapunk.md`。

---

## 6. 与 `engine/` 的对应关系

| 数据 | JSON 位置 | 引擎 |
|------|-----------|------|
| 铁甲战士牌组 | `characters/ironclad.json` | `deck.IRONCLAD_A10_DECK` ← `load_data.build_deck_pile()` |
| 卡牌数值 | `cards/*.json` | `combat.CARD_*` ← `load_data.build_card_stats()` |
| 海洋混混 | `encounters/seapunk.json` | `combat.SEAPUNK_INTENTS` ← `load_data.build_intents()` |
| 其它角色/遭遇 | `data/sts2/` 等 | **已录 JSON，`solver_status: data_only`**，引擎待扩展 |

**多重集表示**：当前试点 `Pile = (打击, 防御, 痛击, 诅咒)` 四元组；其它角色扩展槽位后按 `CARD_ORDER` 类推。

**新增内容**：先写 JSON + `first_fight_model`（见 `docs/角色战斗机制.md`），再改 `load_data` / 战斗引擎；避免双份硬编码。
