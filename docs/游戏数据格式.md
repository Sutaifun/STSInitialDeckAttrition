# 游戏数据格式

> 静态 JSON + Markdown，不与游戏本体联动。  
> 求解器**目标**是从这些文件加载；**当前**试点仍部分硬编码于 `engine/`（见 §6）。

---

## 1. 目录约定

```text
data/
├── sts1/                    # 塔1（待建，结构同 sts2）
└── sts2/
    ├── cards/               # 单卡定义，一卡一文件
    │   └── {card_id}.json
    ├── characters/          # 角色初始牌组与遗物说明
    │   └── {character_id}.json
    ├── encounters/          # 遭遇战（含怪物意图、血量）
    │   └── {encounter_id}.json
    └── pilot_*.md           # 某场试点的设定摘要（人类可读，非机器加载）
```

- **`id`**：英文 snake_case，文件名与 JSON 内 `id` 一致。
- **塔1 / 塔2** 分目录；同一张通用卡（如打击）在两作中可各有一份 JSON（数值不同时）或共用（未强制，按录入方便为准）。
- **进阶**：怪物与部分数值用 `low` / `high` 两档；塔2 高进阶对标 **A10**，塔1 对标 **A20**（见 `docs/项目计划书.md`）。

## 2. 卡牌 `cards/*.json`

### 2.1 通用字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✓ | 与文件名相同 |
| `name` | string | | 中文名（展示用） |
| `cost` | int | 攻击/技能通常必填 | 能量费用；诅咒等不可打出可无 |
| `type` | string | | `attack` \| `skill` \| `power` 等 |
| `target` | string | | `enemy` \| `self` 等 |
| `unplayable` | bool | | `true` 表示不能被打出 |
| `keywords` | string[] | | 见 §2.3 |
| `damage` | int | | 攻击单次基础伤害（多段另字段） |
| `block` | int | | 技能获得的基础格挡 |
| `effects` | object[] | | 附加效果，见 §2.4 |

### 2.2 示例

**打击** `strike.json`：

```json
{
  "id": "strike",
  "name": "打击",
  "cost": 1,
  "type": "attack",
  "damage": 6,
  "target": "enemy"
}
```

**痛击** `bash.json`（先伤害后易伤）：

```json
{
  "id": "bash",
  "name": "痛击",
  "cost": 2,
  "type": "attack",
  "damage": 8,
  "target": "enemy",
  "effects": [
    {
      "type": "apply_vulnerable",
      "amount": 2,
      "order": "after_damage"
    }
  ]
}
```

**进阶之灾** `ascenders_bane.json`：

```json
{
  "id": "ascenders_bane",
  "name": "进阶之灾",
  "unplayable": true,
  "keywords": ["eternal", "ethereal"]
}
```

### 2.3 词条 `keywords`

| 值 | 含义 |
|----|------|
| `eternal` | 永恒（局外；不影响局内消耗/变牌） |
| `ethereal` | 虚无（回合末仍在手则消耗） |
| `exhaust` | 消耗（打出后进消耗堆） |

完整战斗语义见 `docs/游戏机制.md` §9。

### 2.4 效果 `effects[]`

| `type` | 字段 | 说明 |
|--------|------|------|
| `apply_vulnerable` | `amount`, `order` | 给予易伤；`order`: `after_damage` \| `before_damage` |
| （待扩展） | | `apply_weak`, `gain_block`, 多段 `hits` 等按需追加 |

多段伤害在**怪物意图**里用 `hits`；卡牌多段若录入，建议 `damage` + `hits`。

## 3. 角色 `characters/*.json`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 角色 id |
| `name` | string | 中文名 |
| `starting_deck` | object[] | `{ "card": "<card_id>", "count": n }` |
| `relic` | object | 遗物说明（可选） |
| `relic.id` | string | 遗物 id |
| `relic.in_combat` | bool | 是否参与**战斗内**模拟 |
| `relic.note` | string | 备注（如燃烧之血仅战后回血） |

示例见 `data/sts2/characters/ironclad.json`。

**牌组引用**：`starting_deck[].card` 必须对应 `cards/` 下已有 `id`。

---

## 4. 遭遇战 `encounters/*.json`

一场遭遇可含多只怪；首场弱怪多为单怪。

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 遭遇 id |
| `name` | string | 显示名 |
| `act` | int | 层数 |
| `pool` | string | 如 `weak`（弱怪池） |
| `biome` | string | 区域（可选） |
| `monsters` | object[] | 怪物列表 |
| `notes` | string[] | 自由备注 |

### 4.1 怪物 `monsters[]`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 怪物 id |
| `name` | string | 中文名 |
| `max_hp` | object | 见下 |
| `moves` | object[] | 意图列表 |
| `pattern` | object | 意图循环 |

**`max_hp`**：

```json
{
  "low": { "min": 44, "max": 46 },
  "high": { "min": 47, "max": 49 },
  "solve": "enumerate_each"
}
```

| `solve` | 含义 |
|---------|------|
| `enumerate_each` | 对 `[min, max]` 内**每个整数 HP 分别求解**，不合并 |

### 4.2 意图 `moves[]`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 如 `A`, `B`, `C` |
| `intent` | string | `attack` \| `defend_buff` \| … |
| `damage` | int 或 `{low, high}` | 单段攻击基础伤害 |
| `hits` | int | 段数；总伤 = 单段（含力量等）× 段数规则见机制文档 |
| `block` | int 或 `{low, high}` | `defend_buff` 获得格挡 |
| `strength` | int 或 `{low, high}` | `defend_buff` 获得力量 |

**`pattern`**：

```json
{
  "opening": "A",
  "cycle": ["A", "B", "C"]
}
```

- 开战第一轮固定 `opening`；之后按 `cycle` 循环。

### 4.3 数值档位

- 标量（如 `damage: 2`）：两进阶相同。
- `{ "low": n, "high": m }`：低进阶 / 高进阶（A10 或 A20）采用值。
- 括号约定与 `docs/游戏机制.md` §6 一致。

## 5. 试点说明 `pilot_*.md`

人类可读的单场设定摘要（角色、怪物、进阶、求解约定），**不是**机器加载的 schema。  
例：`data/sts2/pilot_ironclad_vs_seapunk.md`。

---

## 6. 与 `engine/` 的对应关系（当前）

| 数据 | JSON 位置 | 引擎现状 |
|------|-----------|----------|
| 铁甲战士牌组 | `ironclad.json` | `deck.IRONCLAD_A10_DECK = (5,4,1,1)` 硬编码 |
| 卡牌数值 | `cards/*.json` | `combat.CARD_*` 硬编码 |
| 海洋混混 | `seapunk.json` | `combat.SEAPUNK_INTENTS` 硬编码 |
| 牌种顺序 | — | `deck.CARD_ORDER` → `(S,D,B,X)` 四元组 `Pile` |

**多重集表示**：`Pile = (打击, 防御, 痛击, 诅咒)` 张数，与 `CARD_ORDER` 一致。

后续应增加 `engine/load_data.py`（或同类）从 JSON 构建上述结构；**新增内容请先写 JSON，再改加载器**，避免只改硬编码。

## 7. 录入检查清单

- [ ] 新卡：`cards/{id}.json`，`id` 与 `starting_deck` 引用一致  
- [ ] 怪物 HP 区间 + `"solve": "enumerate_each"`  
- [ ] 意图多段：`damage` + `hits`  
- [ ] 高进阶数值放在 `high` 或 A10 采用档  
- [ ] 不可打出卡：`unplayable: true` + 必要 `keywords`  
- [ ] 试点场：可选更新 `pilot_*.md`
