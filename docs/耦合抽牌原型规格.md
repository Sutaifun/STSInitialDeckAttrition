## 1. 目标

在 **打破「弃牌堆与出牌无关」** 的最小场景下，验证 **B 内核**（通用组合抽 + 层 2 / 敌人回写三堆）的正确性与权重不变量，为后续弱池粘液场（塔1 / 塔2）铺路。

**首个原型范围**（刻意收窄）：

| 项 | 取值 |
|----|------|
| 游戏 | 塔1 |
| 角色 | 铁甲战士 |
| 遭遇 | `small_slimes` **单变体 A**（尖刺 M + 酸液 S） |
| 进阶 | 固定一档（建议 A0 或 A20 择一录入，实现时与 JSON 对齐） |
| 敌人 AI | **固定 / 简化**（不展开 weighted_after 全分支；首版可定死意图序列） |
| 粘液 | 仅 **进弃牌堆** + **打出消耗**（塔1 `slimed.json`） |
| **明确不做** | 塔2 粘液 **打出抽 1**（回合内再抽） |

## 2. 与独立快路径的关系

| 模式 | 何时使用 | 牌堆推进 |
|------|----------|----------|
| **独立快路径** | 无 `add_status_to_discard`、无出牌改池、标准档虚无仅烧诅咒 | `end_turn_piles(hand_at_turn_start)`；前沿仅含战斗 CS |
| **coupled（本规格）** | 遭遇含塞粘液，或角色 `discard_pile_coupled_to_plays` | 敌人行动 / 出牌 / 回合末 **写回** `(draw, discard, exhaust)`；必要时 `hand` |

**切换条件（实现约定）**：

1. 遭遇 JSON 含 `add_status_to_discard` → 强制 coupled。  
2. 角色 JSON `discard_pile_coupled_to_plays` 非空（如猎手 `bane_only`）→ coupled。  
3. 否则 → 独立快路径（**铁甲 vs 海洋混混** 必须走此路径，见 `tests/test_pilot_golden.py`）。

不得为粘液单独引入第三条平行调度器；coupled 与独立路径 **共享** `weighted_draw_at_turn_start` / `_wdraw_rec`。

---

## 3. 状态键

coupled 模式下，层 2 DP / 可选汇合 memo 的状态键 **必须** 包含：

```text
(战斗 CS, draw, discard, exhaust, hand)
```

其中：

- **战斗 CS**：与现 `CombatCS` 同构（敌 HP、格挡、力量、易伤、意图索引等压缩元组）。  
- **draw / discard / exhaust / hand**：多重集张数；原型须扩展 **`Pile` 槽位含粘液**（或等价 status 槽），不可沿用仅四元组 `(打击, 防御, 痛击, 诅咒)` 假装无粘液。  
- 洗牌前弃牌堆 **顺序忽略**（与协议 §9 一致）；洗牌时机与现 `draw_scheduler` 一致。

**禁止**：coupled 场仍用「仅按上手 `TurnPiles` 共享前沿、出牌不看牌堆」的独立 `solve_encounter` 路径。

## 4. 机制细则（原型内）

### 4.1 敌人塞粘液

- 触发：`add_status_to_discard`，`card: slimed`，`amount: 1`（尖刺 M **Flame Tackle**）。  
- 时机：该敌人意图结算后，向 **弃牌堆** 增加对应张数粘液（多重集 +1）。  
- 不塞牌的小怪（酸液 S 等）按固定 AI 只造成伤害 / debuff。

### 4.2 粘液（塔1）

- 费用 1，**无其它效果**；打出 → **exhaust**（不进弃牌堆）。  
- 不打出 → 回合末与其它手牌一样进 **弃牌堆**（除非未来扩展虚无类 keyword）。  
- **分支**：层 2 对「本回合是否打出每张粘液」须分裂后继牌堆；不得用 `hand_at_turn_start` 整手入弃而忽略出牌。

### 4.3 层 1 抽牌

- 每回合初：对 **当前** `(draw, discard, exhaust)` 调用 `weighted_draw_at_turn_start`，权重乘积规则不变。  
- **不**假设 10 / 11 / 12 张闭式循环；池大小随塞牌与消耗变化。

### 4.4 层 2 与停止条件

- 仍用 **最小总战损** + `best_kill ≤ surv` 停止延长（`docs/求解器设计.md` §4）。  
- 本回合可击杀 → 只走击杀分支（§5.1）等剪枝在 coupled 下仍适用，但须基于 **含牌堆** 的真实后继。

## 5. 权重不变量

实现 coupled 引擎后，**每条完整路线 ω** 须满足：

| 不变量 | 检验 |
|--------|------|
| 叶权重和 = 1 | `Σ_{ω} w(ω) = 1`（`Fraction` 精确） |
| 单步权重 | 每步 `ways / C(n,k)` 与协议 §9 一致 |
| 打 / 不打粘液 | 两条出牌线后继 `(draw, discard, exhaust)` **不同**；且与手算小例一致 |
| 塞牌后池大小 | 敌人塞 1 粘液后，循环池张数 = 原池 + 1（直至打出消耗） |

建议手算用例（验收时至少跑通）：

1. **仅塞牌、不打粘液**：若干回合后粘液留在弃牌堆，权重步乘积可手算对照。  
2. **塞牌 + 打出粘液**：粘液进 exhaust，池少 1 张粘液；与「不打」路线池差正确。

- 修改 **铁甲 vs 海洋混混** 独立路径数值或 `tests/test_pilot_golden.py` 金标。

## 7. 验收标准（实现任务另开）

下列为 **未来实现 PR** 的合并条件；**本阶段 0 不要求通过**。

1. **模式开关**：`small_slimes` 变体 A 走 coupled；`seapunk` 仍走独立快路径且金标测试全绿。  
2. **权重**：原型遭遇上 `total_weight == 1`（浮点容差 ≤ 1e-9）。  
3. **手算对照**：§5 至少 2 个小用例有单元测试或 JSONL 导出可复核。  
4. **语义**：打出 / 不打粘液导致的后继牌堆与 §4.2 一致（自动化断言或导出回放）。  
5. **文档**：实现 PR 更新 `data/sts1/README.md` 或遭遇 `notes`，标明 AI 简化口径。  
6. **回归**：任何共享 `draw_scheduler` / 牌堆写回改动后，`tests/test_pilot_golden.py` 必须通过。
